## 每笔生产前的准入

1. 先定义最终实体：独立角色、共同互动角色、完整房间、前/中/背景层、UI 总图或独立 UI 组件。不能让生成结束后才决定输出是什么。
2. 同时写清原始画布、alpha 可见边界、1024×600 上的可见尺寸、相机、家具比例、地面/座面接触点、脚底锚点。画布尺寸不等于角色尺寸；不能为省缓存把正式人物缩小一半而保持原房间不变。
3. 阅读对应模块、当前 `--help` 和产品参数契约。不同模块的 `standard`、帧数、抠图、分辨率、默认模型不能相互套用。枚举里出现的选项也可能暂未开放。
4. 核对模板目录或输入素材职责。模板大小/数量是固定契约，提示词不能改。需要新模板时按官方规则展示候选让用户选；已有明确选择不重复确认。
5. 明确报价、剩余本轮预算和必要附加费。角色身份/构图未稳定时先低成本验证，不能默认所有实验都用 Ultimate。未确认费用不收费；策划 Agent 没有单次硬封顶，不拿它作未知费用的自动编排器。
6. 逐笔、串行记账。收费提交只执行一次；断线先恢复原 Job。余额差只是观察值，还需和报价、退款及并发/到期情况对照。下载失败不是生成失败。
7. 源图/生成原件保持不变；只导入官方声明的最终媒体。私人照片、录音、声纹、密钥不因积分授权而获得上传许可。

## 人物与家具互动

当前正确起点是**多参考图编辑共同关键帧**，不是先生成“坐在空气里”的两个人，再试着摆到沙发上。

- `image-edit-run` 支持 1–8 张 `--reference-image`。通常主图加一张辅助图即可；双人身份确需三张时，每张职责明确：房间/家具、男方、原版千千。
- 提示词描述接触关系：臀部落在坐垫、背部与靠背、膝盖弯曲、鞋底高度、相机与家具比例。简短自然语言，不堆叠否定词。
- 先验收一张完整互动关键帧。正式原版千千不被这张派生姿态覆盖。
- 分离角色/家具时，区分**独立去背景**和**生成式编辑提取**。后者可能重画、放大、重排；`--strict` 不保证像素相同或坐标不变。必须测量并比较，不能称为精确遮罩。
- 真正可重用的共同角色层需验收双人间距、共同座面锚点、尺寸、透明边缘与原房间的接触。在来源发生变化时只允许可追溯、整体一致的技术变换；不能逐帧重画、遮腿、自动居中伪造接触。
- 原人物还需独立移动时，不用共同静态图替换整个 OS 的两位居民；共同动画仅用于明确的日常互动状态。

当前未核验到网页某个独立命名的“双素材互动”按钮；不能据此声称网页没有该能力，也不能编造 CLI 子命令。多参考编辑和下述动作迁移已由本机 CLI/样本验证。

## 已有动作的迁移与修改

这两类命令不能混用：

- `animation-edit-run`：对现有 GIF/WebP 的帧做一致性修改，例如服装、特效、皮肤；目标是保留既有帧布局和时间。恢复 workflow 为 `frames_edit`。
- `meowa-animation-edit-run`：视频/动图参考驱动的动作编辑，会重采样动作。`--primary-reference video` 是修改视频角色；`--primary-reference image` 是**让图片中的角色执行参考动画动作**，并要求 `--image-file`。恢复 workflow 为 `meowa_animation`。

后者适合用原版千千的已知步态指导男方动作，原版素材只作为只读参考。需要 `edit_intent`、`video_description`，带图片时还需 `image_description`；先人工审阅文本。`meowa-animation-edit-prompts` 生成的是可修改描述，不是成品动画。

参考动画最长 4.5 秒、32 MiB；像素参考每边最多 320px，图和视频的原始尺寸一致。≤2 秒得到 16 帧/2 秒、2–3 秒得到 24 帧、3–4.5 秒得到 32 帧，不保持源动画的 800ms 或原帧数。要改变运行速度，必须记录新时长并验证步态与逻辑步速，不能静默声称原时间轴完全保留。

## 新动作与关键帧

- 简单轻呼吸可选 `animate-run` V1 Pixel；复杂互动优先 V2。不能用 V1 的 `other` 代替不适合它的复杂动作。
- V1 Standard：每边≤256px，帧数 4/6/8/10/12/16；Advanced 每边≤320px，3–16 的整数帧。Padding 在限制内，不会缩放源人物。
- V2 `meowa-animation-run`：像素每边≤320px，8/16/24/32 帧；像素默认 Detailed，HD 默认 Standard。`medium` 是当前 CLI 的 Detailed，`advanced` 暂未可用，不能照着“高级”字面选择。
- 动作首姿正确后再动画。行走首姿要迈步；坐下、挥手、收起等动作先有正确接触姿态。源图不适合时不要用长提示词强救。
- `--last-image-file` 提供精确终姿；它强制非循环，未指定帧数时默认 24 帧，不沿用普通 V2 的 16 帧。
- `keyframes-run` 可指定至少两个关键帧、包含第 0 帧和逐帧 strength，用于需要中间接触状态的动作。它的帧数集合与 V1/V2 不同。
- `--high-frame-rate` 会保留更多实际生成帧，影响抠图批次、文件/缓存成本；不能只按请求的 16 帧计价。
- `--auto-scale-to-input` 是 HD 专用、平滑恢复，不是像素角色的缩放修复开关。
- 生成动画的循环元数据不等于首尾无缝。逐帧和播放都要检查亮度、身份、手脚、锚点与循环边界；保留原件和有背景版本。只修经过确认的坏帧，不为凑帧数随意删帧。

## 方向、像素与风格

- `character-multi-view-run` 适合批量八方向静态图，但左右通常镜像，不能当成物理一致的转身。非镜像转身可用 V2 的 32 帧原地 360°，逐帧挑选方向后再验收。
- 固定像素预设优先服务精确规格。`large_portrait` 当前目录为 2K、默认 2 个、128–256 档；不能因为名字带 large 就承诺一个 256px 动画角色。
- `custom-size-pixel-gen-run` 是一个物件的指定尺寸生成，不用于素材包；复杂参考的稳定性低于合适的固定预设，`fill-canvas` 不保证填满宽高，`strong-pixelation` 也不保证身份/尺寸合格。
- `pixel-universal-gen-run` 固定大 4:3 画布，支持 standard/top-down；适合自由像素场景/素材包，逐资产控制与质量弱于专用预设，不作为默认高质量主角路线。
- 通用 Image2.5 生成“像素风”不保证原生像素网格。颜色、轮廓约束和精细像素风格应分别验收。Nano Banana 的形体控制可能更适合某些严格轮廓任务，不能只因习惯一直选 Image2.5。
- 已经由像素工作流处理的结果不再二次像素化。`pixelate-run` 是明确的像素转换，不是无损压缩或任意尺寸修复工具。
- `self-loop-run` 解决静态图的上下/左右接缝，不是给角色生成循环动作。

## UI、组件、克隆与变体

- `ui-gen-run` 是带原生透明/组件检测的总图生成，也能生成普通资产包。默认不是逐个 PNG 下载。本次 API 最终媒体只有总 PNG；七个 PNG 实际由官方本地 splitter 导出，不能混淆来源。
- `ui-gen-run --mode extract` 是生成式提取/重排，不是原房间的精确分层器。
- 官方 `split-components.py` 依据 alpha 或外部连通背景切分，不懂“桌子/人物”的语义，接触的物体会连在一起。先用默认最小面积检查，避免较高阈值静默丢掉星星、蝴蝶结等细节。
- `asset-clone-run` 用于同风格网格资产。`clone-count` 为 1/4/9/16/25/36 个参考网格，不是双人互动的人数；一张包含 N 个物体的总图应保留 count=1 并在完整提示词中描述 N。
- `one-click-upgrade-prompts` 是免费提示词规划，随后 `one-click-upgrade-run` 接受 1–8 个审阅后的变体提示词，适合同一信封/物品的升级状态。不是精确控制人物与沙发关系的首选。
- 中文、日期、动态状态和可点击控件保留在 LVGL。AI 装饰图不能烘焙业务文字或代替可交互 UI。

## 场景与地图

- 完整绘画背景不等于可走地图。可行走区、足底投影、家具占地、实际触摸区、遮挡层必须单独验收。
- 需要原生三层横卷场景时有 `side-scrolling-map-run` / `hd-side-scrolling-map-run`。这两者输出前/中/背景，接受三段文本，不接收下载的地图预设；不能假定它们能无损拆开当前三分之四视角室内。
- 斜角/六边形先从官方地图参考目录下载合适结构。像素斜角保持原图中心锚点、128×64 逻辑菱形及邻接偏移，不能裁掉透明边后按外接框拼接；HD 的平滑缩放规则和像素不同。
- top-down dual-grid 是 64×64 无透视材质输入，输出 4×4/256×256 过渡图集。房间插画、人物或大照片不是材质。foreground/background 单地形可去背景复用；dual 绑定两种材质并禁用去背景。
- `image-expander-run` 可依据四邻图和坐标延展地图；导出支持整图、分片和 Godot 4 场景。Godot 导出不是 LVGL 页面，仍需符合用户的“由 Meowa 做场景美术”约束，不自行拼排当前小屋。
- 地图应使用官方本地预览器检验实际排列、接缝与层位置。预览器或参考输入不能冒充 LVGL 运行画面或生成成品。

## ESP32 资源与验收

正式 Qianqian 保持原版；男女站立显示约 198–210px，以 1024×600 实际画面检验。座面、桌面与人物的比例是准入条件，不因单独 PNG 看起来好看就通过。

沿用 `.lwr` / `.lwp`，不另建不兼容资源格式。当前 RGB565+A8：256² 每帧 196,608 B，320² 每帧 307,200 B；1024×600 不透明背景 1,228,800 B。全屏 alpha 帧 1,843,200 B 超过项目现有 1,250,000 B 单帧上限，不能把整个高清互动场景逐帧无脑导入。原图可作构图依据，运行时仍需经过验收的有限资源层与按需帧。

不能为动画缩小主角来回避内存设计。必要时控制缓存帧数、页面并存、预读与分层范围；分别记录文件缓存、LVGL lease、背景、转换层、显示缓冲和系统开销。Windows 通过不等于 ESP32 板测。

验收顺序：身份与画风 → 原生尺寸/透明 → 人物家具共同尺度 → 接触与遮挡 → 帧连续性/首尾 → 真实 LVGL 触摸/生命周期 → 内存峰值/缺资源 → 用户美术验收。任一阶段失败不向后包装成“正式素材”。
