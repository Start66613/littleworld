## 这一版有什么

### 1. 《拾取回忆》首启故事（新系统）
- 新覆盖层 `OS_OVER_STORY`（`lw_os.c` 的 `build_story()`），八步：
  开场（暗场，「倩倩，这份礼物，要你亲手打开。」）→ 六个碎片
  （相遇 / 留给你的位置 / 普通日子 / 一起去过的地方 / 还好有你 / 坐过来吧）
  → 收束（「两周年快乐」+「这间小屋子装不下全世界，但装得下我们两个。」+ 落款 2026.12.08）。
- 仪式感来自舞台本身：房间背景的遮罩随碎片拾回逐片变薄（225→95 opa），
  第六片时拍立得换成沙发上的双人烘焙动画（锚点 516,368，与宠物页/待机主屏同一校准点）。
- 每片有进度点（6 点）、「拾起这一片」按钮、右上角「跳过」（直达收束；只有点
  「进入小世界」才算看完）。
- 剧本文案 v1 全部集中在 `build_story()`上方的 `story_fragments[]` 表里，
  对照真实照片改字只需要改这张表。
- 照片现在用相册演示的六张示例场景并如实标注「示例照片」；真照片就位后换这里
  与待机轮播同一处素材来源。

### 2. 故事进度持久化（不动存档格式）
- 平台存储钩子是通用键值（设备端 = 本应用 NVS 命名空间内的 blob，主机端 = 一文件一键），
  故事用自己的键 `lwstory` 存 16 字节版本化记录（LWST v1 + crc32）。
- `.lwr` 存档格式、分区、NVS 布局一概没碰。
- 语义：0 未开始，1..6 已拾回片数，7 已完成；写入单调递增，重看不会倒退进度；
  记录损坏/缺失一律读作「未开始」（对礼物来说是安全的失败方向）。
- 断电续看：每拾一片立即落盘，重开故事从「已拾数 + 1」片继续。
- 已用文件后端平台替身实测：fresh=0、set 后跨进程保留、低值写入被忽略、crc 损坏回退 0。

### 3. 自动播放只在真机
- 首启自动播放在 shell tick 里，`#ifdef ESP_PLATFORM` 门控（与仓库既有的
  `LW_VISUAL_WARM` 同一判别方式）：每次上电、开机动画结束、无其他覆盖层时，
  未完成的故事自己打开一次。
- 主机构建永不自动打开——截图基线与 Windows UI 套件的流程不受影响；
  主机上从回忆页入口同样可以完整体验。

### 4. 回忆页有了故事的家
- 回忆页「今日」标签页底部新增整幅卡片「我们的故事 · 拾取回忆」，
  文案与按钮随进度变化：开始故事 / 继续故事（走恢复语义）/ 重看故事
  （`lw_os_story_replay()`，从头播放且不降低已存进度）。

### 5. 桌面收敛（只加不减）
- 桌面新增一排礼物版入口：回忆 / 陪伴 / 音乐 / 一起玩 / 设置，
  全部复用既有页面控件（OC_MEMORIES / OC_PET / OC_MUSIC / OC_GAMES / OC_SETTINGS）。
- dock 保持六个入口不变（「游戏」标签改为「一起玩」），控制中心、房间热点、
  相册入口一概未动——主机套件按控件 id 点按的所有目标都仍然注册在位。
- 游戏页正式成为「一起玩」中枢：标题与应用名改名，新增第四张卡「小冒险」，
  通过 `lw_os_open(OS_RPG)` 进入双人 RPG 页；卡片改四列布局（224 宽）；
  烘焙徽章素材只有原三款游戏有，RPG 卡保留朴素圆点徽章。
