## 二、固件里真实存在的缺陷（已定位、本轮不修）

### 1. `lw_pack` 的命名空间上限从 2 提到 5，但仍是编译期常量

`LW_PACK_MAX_ACTORS` 现在是 5（male / qianqian / v42 / v42ui / v43skin），
`LW_PACK_MAX_SPECS` 64，`LW_PACK_MAX_FILES` 8。
如果再加入第 6 个视觉命名空间，会静默失败（`LW_PACK_ERR_ACTORS` 计入 `s_report`，但界面只是少一块内容）。
**建议**：把这三个上限挪进 `lw_art.c` 的配置结构，或者在启动时打一行 `packs: 6/6 namespaces`。

### 2. 可选包缺失时没有 UI 提示

`lw_art.c` 对 `LW_PACK_ERR_OPEN` 静默跳过是**正确的**（旧卡也要能用），
但如果卡上有 `daily.lwp` 而它损坏了，界面只会退化成静态图，用户看不出原因。
`diag` / `content` 命令里有 `s_report`，但界面上没有。
**建议**：在设置页"存储"分区加一行"资源包：6/6"，或控制中心角标。

### 3. `lw_ambience_previewing()` 声明了但没有调用点

新增的声明在 `lw_ambience.h`，实现被链接器回收（`-ffunction-sections`）。
功能不受影响（预览走 `lw_ambience_preview()` 自己那套），但这个 API 目前是空壳。
**建议**：要么删掉声明，要么在设置页用它显示"预览中"。

### 4. Dock 展开态文字拥挤

六个入口 76×52，18px 字体下中文标签贴边。
用户已知，同意记录为后续视觉修复，**不影响第一轮硬件显示测试**。

### 5. RPG 任务本与返回箭头轻微重叠

`17-rpg-room.png` 可见。视觉层的小问题。

### 6. 相册空态标题与副标题距离偏紧

`21-album-empty.png` 可见。

## 四、已知的"看起来像 bug 但其实是设计"的几件事

- **`littleworld: wifi=no-backend`**：os 配置本来就没编 Wi-Fi，正确。
- **`brightness: backend reports Unsupported`**：只在 diag-b/diag-c 诊断构建里出现（固定背光），os 配置能调。
- **`card: no card` 但界面有画面**：内置了 `idle` 帧与默认场景，这是降级路径，不是失败。
- **`19:30 … · 演示`**：没有 RTC 也没有 SNTP，时间只能是演示态；真实时间要靠 Wi-Fi 校时。
- **os 与 noaudio 镜像大小接近**：两者都链接了同一套 UI，noaudio 只是不初始化音频后端。
