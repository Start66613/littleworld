## 我之前没有用对的地方

### 1. 把小画布建议当成了全项目角色尺度

官方建议尽量使用紧凑动画源，不能据此将本来可见约 198–210px 的主角缩成约 100px，仍放在原 1024×600 房间里。用户截图里人物相对沙发过小，是我的集成错误。相机、人物、家具必须共享尺度；不能只检查 pack 的 width/height 或编译通过。

目前 RPG 已改回直接复用正式 256px 原版角色和原时间表。`v42-scale-review/17-rpg-room.png` 是真实 LVGL 修正截图，493 项回归通过；这不表示后续未测代码及整轮 V4.2 已交付。

### 2. 错把“坐姿”当成“坐进这个沙发”

独立生成空气坐姿再摆进房间，不能保证臀部、坐垫、靠背、鞋底、角色间距和镜头一致。正确流程是角色与家具多参考图共同编辑，先得到完整互动关键帧，再审查可复用角色层和动作。

这次多参考图生成确实改善了接触与比例，但派生画风和最终用户美术验收仍待确认；不覆盖原版千千。之前六笔独立坐姿/待机/困倦实验共 **118 积分**，现不作为最终日常方案，费用不从账本抹掉。

### 3. 把生成式提取当成同坐标分层

`image-edit-run --strict` 仍是生成式编辑，不是精确语义分割。22 积分的工坊书桌提取改变了几何和位置，不能用作原房间前景；明确拒收，不通过人工拼回场景掩盖。

双人透明提取也放大、重排了角色。其输出只能作为需要明确技术变换与接触复核的派生源，不能叫“精确对齐层”。现有 1/3 技术归一化不是 Meowa 原生保证，来源和误差必须明示；以后优先评估保留像素的去背景路径及真正的分层输出，仍需检查是否保留了正确对象。

### 4. 没有优先复用已有动作

官方参考动作编辑的 `--primary-reference image` 可以让男方图片执行参考动画。男方右行样本已按此生成，256×256、16 帧，可见高度约 207–211px，服装/身份/步态已经看过逐帧图；左行已返回，尚未完成视觉审查。它比逐方向“首姿重做→新动画”更符合现有资产条件，但仍不能凭一例保证所有方向合格。

这条命令与 `animation-edit-run` 不同：后者偏向修改既有动画帧；参考动作编辑会重采样，800ms 的 8 帧源变成 2 秒/16 帧，不能谎称保留源时长。

### 5. 对 UI 生成和切分的说法不够严谨

本次 UI API 下载的是总 PNG，没有单独下载的组件分割 JSON。七个组件来自官方本地 splitter。splitter 基于连通 alpha/背景，不理解家具语义；UI extract 也可能生成式重排。较高的最小面积阈值可能丢掉装饰星星，需回看全部组件，不能只验收大块数量。

### 6. 初试质量档和模型选择过于固定

Image2.5 的色彩表现有价值，但官方明确提示其严格像素/形体约束不总是最强。不能所有任务都默认 Image2.5 + 2K Ultimate。构图/互动未明确时应先最小样本；模板合适时用原生像素路径，形体敏感时评估 Nano Banana，并分别验收网格、身份和颜色。

### 7. 把接口成功、工程测试和美术合格混在一起

HTTP success、PNG 有 alpha、493 项 UI 检查和用户认可画风，是四件不同的事。独立坐姿虽然返回成功，仍有配合房间的问题；书桌提取虽下载成功仍拒收。原件、候选、拒收和正式导入应在清单中分开标记。

## 之前未充分使用的高级能力

以下已读文档和实际参数；除明确写有样本者外，尚未收费实测。

- **多参考图共同编辑**：人物与沙发、双人同框、手持物件。先审查共同关键帧；角色身份和场景接触由不同参考承担，不能把两张图简单并排当互动。
- **图片主导的参考动作迁移**：`meowa-animation-edit-run --primary-reference image`，已用于右行样本；方向、服装和节奏仍需逐动作验证。
- **首尾帧控制**：V2 `--last-image-file`，适合坐下/起身/信封开合两端明确的动作；默认帧数和循环行为会改变。
- **多关键帧与 strength**：`keyframes-run`，适合“靠近→接触→完成”中间状态也必须正确的动作；不能混用 V2 的帧数集合。
- **已有动画逐帧编辑**：`animation-edit-run`，适合换衣、统一细节或修改效果，目标是保留时间/布局；不是参考动作迁移的别名。
- **八方向与不镜像转身**：静态多视图常镜像；需要物理一致时用 V2 32 帧旋转后挑方向。不是一次调用就保证八方向、像素一致和可动画。
- **同源变体与克隆**：one-click upgrade 适合信封/奖励/物品状态；asset clone 适合同风格资产族。网格数不是互动人数，不能拿 clone-count=4 表示两人两件家具。
- **原生分层场景**：side-scrolling 输出前/中/背景层；它服务横向场景，不应被硬当成当前室内画面的无损分层器。
- **地图延展和分片导出**：image expander 可用邻图继续区域，导出分片/Godot；后者不是直接可运行的 LVGL 工程。
- **材质、dual-grid、斜角/六边形及预览器**：有严格 64px 输入、逻辑 footprint 与锚点契约；适合未来地图，不能以“高级”为由推翻当前视角或恢复用户拒绝的手工拼排美术。
- **完整 Spine 工作流**：生成、部件改绘、直接替换、全身重绘、清理、网页骨骼/关键帧编辑都存在。当前 Little World 未集成其运行链，精细像素和资源成本需评估，暂不引入。
- **音效、音乐、TTS/克隆音色、拼豆、策划 Agent**：理解其用途和输入边界。音频应等后端和具体内容；私人录音不能直接上传。策划按 token 和工具分别计费，没有单任务硬上限，不在学习时盲目启动。

所有 44 个产品条目的逐项用途、限制、使用状态与项目适用性见 `skill-review/CAPABILITIES.json`，另补充独立 pixelate、Game Designer、自定义目录和本地工具。

## 我现在仍不能声称已经掌握的部分

1. **网页独立的“双素材互动”入口**：当前完整 Skill/参数契约证实了多参考编辑及图片主导动作迁移，但网页入口两次加载超时。没有核验那个具体按钮名称、独立定价和导出结构；既不说它不存在，也不编造 `asset-interaction-run`。
2. **所有模板的实际画风与产物**：已读目录不等于 三个目录中的模板都生成过。`large_portrait` 默认 2 个、128–256 档，也不等于一张精确 256px 的最终主角动画。
3. **无损人物/家具分离**：生成式提取已有失败实证，透明和同坐标必须分别验收。独立去背景可保持几何，但未证明能从复杂房间中只保留想要的对象。
4. **未跑过的高级输出**：Spine、地图分层、扩图、音频等尚无本项目成品样本；只完成文档/参数审查，不写“生产验证通过”。
5. **服务器可用性与报价**：参数解析允许某值不等于服务当前开放。V2 Ultimate/advanced 抠图等明确暂不可用；目录未给完整报价的路径仍需单独核价。
6. **硬件表现**：Meowa 的 2K 图、1080P 动画和 Windows 运行成功，不证明 ESP32 内存、TF 吞吐或实际帧率已通过。本轮没有设备操作。

另外，文档也需交叉核对：快速开始的 Spine 段落仍写 Image2 为默认，而专题、产品契约和当前解析器为 Image2.5；参考动作的 `primary-reference` 在参数契约和实际帮助里明确列出，专题叙述没有同等展开。我之前只沿路由读常用段落，没有系统比对这些层次，确实漏掉了重要选项。后续遇到差异记录证据、使用明确产品参数，不凭记忆补命令。
